How it works

Three steps, and the last one is optional.

  1. 1

    Keep profiles

    A profile is a list of KEY=value pairs. Mark a value as secret and it stays masked until you ask to see it. Bring in an existing .env file or start empty.

  2. 2

    Apply one

    HyperEnv writes one generated file that your shell reads at login, so every terminal you open from then on has those variables. Terminals already open keep theirs; one source line updates them.

  3. 3

    Undo

    Every variable goes back to the value it had before, and the ones that did not exist are removed.

Command line

The same engine, from the terminal.

The hyperenv command ships inside the app and also runs on its own. Check what a profile would change before applying it, apply it, and take it back.

  • plan shows the change without making it
  • drift checks that a new terminal matches what is applied
  • export writes POSIX, .env or Docker format
  • --json on every command, for scripts

Editors

Switch without leaving the editor.

The plugins call the same command, so the editor, the app and the terminal always agree on what is applied.

Details

What it does to your machine.

No sudo
Everything lives in your home folder. Your shell's startup file gets one small marked block, added once and removed on request.
Your shell
zsh, bash, fish and PowerShell.
Secrets stay masked
Shown as dots in the app, the plugins and the terminal, unless you ask to reveal them.
Nothing leaves the computer
No account, no sync, no telemetry. Profiles stay in a local file.
Three platforms
A native app on macOS. A desktop app for Windows and Linux. The command on all three.
Open source
MIT license. Read the code, file an issue or send a pull request on GitHub.
